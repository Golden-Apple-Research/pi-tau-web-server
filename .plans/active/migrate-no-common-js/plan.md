# Plan: Migrate tau to pure ESM TypeScript (eliminate all CommonJS)

## Goal

Make the entire tau repo a single, unambiguous ESM TypeScript world: no `require()`, `module.exports`, `__dirname`, or `require.main` anywhere in source, tests, or build output. This kills the `MODULE_TYPELESS_PACKAGE_JSON` warning from `npm test` and unifies the module format of the repo's own code with the pi extension (`src/pi-extension/tau-tree.ts`, which must stay ESM because pi's loader `jiti.import()`s it and expects a `default` export). **Confirmed scope: include the full migration + polish (NodeNext rename and copy-katex → TS).**

## Findings from inspection (why this is safe)

- Source already uses ESM `import`/`export` syntax everywhere with NodeNext-style `.js` extensions; output is CJS only because `package.json` lacks `"type": "module"` and `tsconfig.server.json` uses `module: Node16` (which *preserves* package format → CJS).
- Only genuine CJS-isms in `src/server/`: `require()` calls in auth.ts, config.ts, model-utils.ts, sessions.ts, server-main.ts; `__dirname` in sessions.ts:45; `module.exports = {...}` (52 named exports) in server-main.ts:954; the entry pattern in tau.ts (`require.main === module` + `module.exports = tau`).
- Tests (14 × `test/*.test.ts` + `test/e2e/*.e2e.ts`) are hybrid: runtime `require()` + `import type`; they import the *built* `../bin/tau.js` (never src/server), so Node type-stripping only ever handles test files + tau-tree.ts — verified no `enum`/`namespace`/parameter-properties in those, so plain type stripping works after conversion.
- `src/public/` is already pure ESM (`module: ES2022`, Bundler resolution, `.js` extensions); browsers ignore package.json, so `"type": "module"` has zero effect there.
- `bin/` is gitignored build output (regenerated by `npm run build`).
- `scripts/copy-katex.mjs` is already ESM (uses `createRequire` deliberately to resolve katex — legal ESM API) and contains no type annotations, so renaming to `.ts` is a zero-content-change conversion runnable via Node's default type stripping.
- Empirically verified: `node -` stdin and `node -e` default to CommonJS regardless of `"type": "module"`, so the `require`-using heredocs inside `test/container-launcher.test.sh` are unaffected.
- No repo code depends on the CJS shape of `bin/tau.js` except tests (named destructuring) and the npm `main`/`bin` fields — all preserved by named exports + a default export.

## Changes

### 1. `package.json`
- Add `"type": "module"`.
- Change `"build"` script: `node scripts/copy-katex.mjs` → `node scripts/copy-katex.ts`.
- Keep `main`, `bin`, `files`, `engines` unchanged (all ESM-compatible).

### 2. `tsconfigs` — Node16 → NodeNext
- **tsconfig.server.json**: `"module": "Node16"` → `"module": "NodeNext"`; `"moduleResolution": "Node16"` → `"moduleResolution": "NodeNext"`. (Identical emit/resolution behavior now that `"type": "module"` is set; clearer intent.)
- **tsconfig.test.json**: same rename of `module` and `moduleResolution`. Keep `noEmit`, `allowImportingTsExtensions`.
- **tsconfig.public.json**: unchanged (already `module: ES2022` + Bundler; browser code, unaffected by package type).

### 3. `src/server/*.ts` (6 files change; tree.ts, types.ts already clean)
- **auth.ts** — `const crypto = require('node:crypto')` → `import crypto from 'node:crypto'`.
- **config.ts** — `require('node:fs')` / `require('node:path')` → imports.
- **model-utils.ts** — `require('node:child_process')` → `import { execFile } from 'node:child_process'`.
- **sessions.ts** — 4 `require(...)` calls (fs, path, child_process, ws) → imports; `path.resolve(__dirname, '..', 'src', 'pi-extension', 'tau-tree.ts')` → `import.meta.dirname` (engines ≥22.19; available since Node 20.11).
- **server-main.ts** — 7 `require(...)` calls → imports (http, fs, path, os, child_process, readline, ws); `module.exports = { <52 names> }` → `export { <same 52 names> }` (all are in-scope top-level declarations; tsc errors on `module.exports` in ESM context, forcing the conversion).
- **tau.ts** (bin entry) — rewrite to pure ESM, preserving both consumption shapes:
  - keep `#!/usr/bin/env node` shebang (tsc preserves it);
  - `if (import.meta.url === pathToFileURL(process.argv[1]).href) startCli();` replaces the `require.main === module` check;
  - `export * from './server-main.js'` so `import { server, ... } from 'pi-tau-web-server'` / `from '../bin/tau.js'` keeps working;
  - `export default` a namespace object (`import * as tau from './server-main.js'`) so `import tau from 'pi-tau-web-server'` still yields the same aggregate object as the old `module.exports`.

### 4. Tests — `test/*.test.ts` (14 files) and `test/e2e/*.e2e.ts`
Mechanical per file:
- `const { test, before, after, ... } = require('node:test')` → `import { test, ... } from 'node:test'` (same for node:assert/strict, node:fs, node:path, node:os, node:events, node:stream, ws, playwright).
- `const { ... } = require('../bin/tau.js')` / `require('../../bin/tau.js')` → static named `import { ... }` from the same path.
- Keep existing `import type` lines and the dynamic `await import('../src/pi-extension/tau-tree.ts')` in tree-navigate.test.ts (already extension-explicit; now resolves as unambiguous ESM → warning gone).
- Do NOT touch `test/container-launcher.test.sh` (heredocs verified safe).

### 5. `scripts/copy-katex.mjs` → `scripts/copy-katex.ts`
- `git mv`, zero content change (file is plain JS, valid TS as-is; `createRequire` is legal ESM).
- Runs via `node scripts/copy-katex.ts` (type stripping is default in the supported Node range).
- Removes the last non-TS module in the repo.

### 6. Not changing
- `src/public/**` (already ESM), `public/vendor/` (copied), `bin/` (regenerated), test `.sh` script.

## Verification

1. `git status` clean baseline before starting; one commit per logical step (package.json+tsconfigs, src/server, tests, copy-katex).
2. `npm run typecheck` — all three tsconfigs pass.
3. `npm run build` — succeeds; `head -5 bin/tau.js` shows ESM output (`import ... from './server-main.js'`, shebang intact, no `require`/`exports`).
4. `npm test` — all tests green **and no `MODULE_TYPELESS_PACKAGE_JSON` warning** (the original symptom).
5. CLI smoke: `node bin/tau.js --help` (or equivalent no-network invocation) — proves the `import.meta.url` entry check fires `startCli()` correctly.
6. Grep sweep: `rg -n "require\(|module\.exports|__dirname|exports\." src/ test/ scripts/ bin/` → no hits (`createRequire` in copy-katex.ts is legal ESM and expected).
7. `npm pack --dry-run` — published file list unchanged in shape (bin, public, scripts, src, tsconfigs).
8. Optional: `npm run test:e2e` and `bash test/container-launcher.test.sh` if their environments are available.

## Risks & mitigations

- **Behavioral surface is the 52-name export block** in server-main.ts: if a name is missing from `export {}`, tests fail loudly at import time (tests destructure most of them) — caught in verification step 4.
- **External consumers of `main`**: pi discovers tau via npm (`pi-package` keyword) but tau is bin-first and standalone; no CJS-only consumer found. Default + named exports preserve both interop shapes.
- **Node type stripping limits**: test files and tau-tree.ts contain only erasable TS (verified); no `--experimental-transform-types` needed.
- **Rollback**: `git revert` per commit; `bin/` regenerates from source on next `npm run build`.

## Deviations from this plan (appended after implementation)

The migration shipped as five commits (the four planned steps plus this plan
doc). The changes below record where the implementation differs from what the
plan above describes. Nothing in the plan was silently changed; these notes
are appended for the record.

### 1. Tests import the built server with `await import(...) as any`, not static named imports

The plan's step 4 prescribed static `import { ... } from '../bin/tau.js'`.
That is wrong for 11 of the 15 test files: they set `process.env` (and write
`settings.json`) at module top level *before* the old `require('../bin/tau.js')`
so the server's load-time constants (`SESSIONS_DIR`, `AUTH_CONFIGURED`, ...)
see the test's temp tree. ESM hoists static imports ahead of the module body,
so a static import would load the server with the real environment. Those
files therefore keep the ordering contract with a top-level dynamic import
placed after the env setup:

```ts
const { server, computeUrls, ... } = (await import('../bin/tau.js')) as any;
```

The `as any` is not a loss: `require()` returned `any`, so it reproduces the
old typing contract exactly. It is also *required* for a second reason: the
compiled `bin/*.js` and `public/*.js` are declaration-less JS, and TypeScript
rejects typed imports of them (TS7016). `allowJs: true` (added to
`tsconfig.test.json`, see deviation 3) makes tsc infer types from the JS
instead, and those inferred types are sometimes actively wrong (e.g. the
`buildHistoryItems` union in `test/history-render.test.ts` does not narrow the
way the test code does), so the cast keeps tests on the old `any` contract
uniformly. Files with no load-time env dependency (helpers, live-session-
manager, markdown, history-render) use the same pattern for uniformity.

### 2. tau.ts entry check compares realpaths, not `import.meta.url` vs `argv[1]`

The plan's check `import.meta.url === pathToFileURL(process.argv[1]).href`
fails for npm-installed bins: npm installs `bin` entries as symlinks, and Node
resolves the ESM entry URL to the *realpath* while `process.argv[1]` keeps the
symlink path (verified empirically). The shipped check compares realpaths:

```ts
const isMain = process.argv[1] !== undefined
  && realpathSync(process.argv[1]) === fileURLToPath(import.meta.url);
```

### 3. config.ts had two more CJS-isms than the plan listed

Besides the `fs`/`path`/`os` requires, `findPublicDir()` used `__dirname`
(STATIC_DIR candidate) and `require.resolve('pi-tau-web-server/package.json')`.
Both converted: `import.meta.dirname` and `import.meta.resolve` (with
`fileURLToPath`), preserving the same resolution. This is the file the plan
missed entirely in its per-file list (it listed only auth/config require
calls under step 3 without noting these two).

### 4. tsconfig.test.json gained `allowJs: true` (not in the plan)

Needed so the static/dynamic imports of `../bin/tau.js` and `../public/*.js`
resolve at all under NodeNext. `checkJs` stays off. Consequence: `npm run
typecheck` now requires `bin/` to exist (a prior `npm run build`); the old
`require()` form skipped resolution. `npm test` builds first, so the test
pipeline is unaffected.

### 5. Converting `require()` surfaced ~74 previously masked type errors

`require()` yields `any`, so every value import in the tests was unchecked.
Once typed, node:test/ws/node builtins flagged real sloppiness, fixed as:

- fake pi children (`new EventEmitter()` + stdin/stdout/stderr/pid/kill)
  declared `any` (they are deliberate mocks; ~8 sites across http-routes,
  live-session-manager, pi-rpc-session, e2e);
- done-style `before`/`after` hooks converted to promise-based async hooks
  (`await new Promise<void>(...)` around `server.listen`/`server.close`) —
  node:test's runtime supports both, so behavior is unchanged (8 sites);
- one `process.env.PI_CODING_AGENT_DIR` access in rpc-command.test.ts got a
  `!`: TS narrows env property access to `string` only until the first
  intervening function call, and the access here followed `await
  handleRpcCommand(...)`;
- the execFile-related call sites in src/server (model-utils.ts, server-
  main.ts) needed a one-time cast to the loose `ExecFileFn` shape and
  `ExecException`-typed callbacks — they were `any` before.

### 6. Baseline typecheck was already red in this environment

`npm run typecheck` on the pre-change tree fails with `Cannot find module
'playwright'` — playwright is a devDependency used only by `test:e2e` and is
not installed here. After the migration the same cause yields two errors (the
new `import { chromium }` plus the pre-existing `import type`), both of which
resolve once playwright is installed. Server and public typechecks are clean.

### 7. CLI smoke test must be bounded

`node bin/tau.js --help` does not exit: `startCli()` has no `--help` handling,
it starts the server and runs until SIGTERM (the old CJS bin behaved the
same). The smoke test therefore uses `timeout` and asserts the server binds
the port and shuts down on SIGTERM (exit 124), both direct and via a symlink,
plus a library-import check that the process exits immediately without
starting the server. The default export carries the same 49 keys as the old
`module.exports` (the plan's "52" was a miscount).

### 8. Extras

- `.gitignore` comment updated (`.mjs` → `.ts`).
- `scripts/copy-katex.ts` is a pure rename with zero content change, as planned.
- The e2e file keeps `import { chromium } from 'playwright'` and the
  `await import('../../bin/tau.js') as any` after env setup.
